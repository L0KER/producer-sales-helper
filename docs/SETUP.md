# Настройка Producer Sales Helper

Инструкция для варианта «всё бесплатно, без своего сервера»:

- приложение — статический сайт на **GitHub Pages**;
- данные — в **приватном GitHub Gist**;
- напоминания — **Telegram-бот**, который запускает **GitHub Actions** каждые 15 минут;
- Mini App — тот же сайт внутри Telegram (нужен HTTPS и переменная `APP_URL`).

Все шаги выполняются один раз. Занимает примерно 20–30 минут.

---

## 0. Что понадобится

- GitHub-аккаунт.
- Telegram-аккаунт.
- Браузер на компьютере (лучше Chrome, Edge или Safari).
- Node.js 20+ — только если хотите запускать проверки или бота локально. Для самого приложения не нужен.

## 1. Репозиторий и GitHub Pages

### 1.1. Создайте репозиторий

1. GitHub → **New repository**.
2. Имя: например `producer-sales-helper`.
3. Видимость: **Public** (для бесплатного GitHub Pages).
4. Не добавляйте README и `.gitignore` — они уже есть в проекте.
5. Создайте репозиторий.

### 1.2. Загрузите файлы

Через веб-интерфейс: **Add file → Upload files**, перетащите всё содержимое папки проекта (включая скрытые `.nojekyll`, `.github`, `.gitignore`) и закоммитьте в `main`.

Через Git:

```powershell
cd C:\путь\к\producer-sales-helper
git init
git add .
git commit -m "Producer Sales Helper"
git branch -M main
git remote add origin https://github.com/<username>/producer-sales-helper.git
git push -u origin main
```

### 1.3. Включите Pages

1. Репозиторий → **Settings → Pages**.
2. **Source**: `Deploy from a branch`.
3. **Branch**: `main`, папка `/ (root)`.
4. **Save**.

Через 1–2 минуты сайт будет доступен:

```text
https://<username>.github.io/producer-sales-helper/
```

Откройте его. Должен появиться экран «Добро пожаловать в студию».

> Если сайт не открывается, проверьте **Actions → Pages** и настройки ветки. Файл `.nojekyll` уже в проекте — он нужен, чтобы GitHub не обрабатывал папки через Jekyll.

В приложении можно сразу нажать **«Загрузить демо»**, чтобы проверить интерфейс. Демо-данные потом заменяются своими.

## 2. Приватный Gist и синхронизация

Gist — это файл в облаке GitHub. Приложение и бот читают и пишут один и тот же файл `producer-sales-helper.json`.

### 2.1. Создайте classic-токен

1. GitHub → аватар → **Settings**.
2. Внизу слева: **Developer settings**.
3. **Personal access tokens → Tokens (classic) → Generate new token (classic)**.
4. Note: `Producer Sales Helper`.
5. Expiration: удобно 90 дней или 1 год. Потом токен нужно обновить.
6. Scopes: поставьте **только `gist`**. Больше ничего не нужно.
7. **Generate token** и сразу скопируйте `ghp_…` — второй раз GitHub его не покажет.

> Не используйте fine-grained token, если не уверены, что у него включён доступ к Gists. Classic-токен со scope `gist` — самый предсказуемый вариант.

### 2.2. Подключите Gist в приложении

1. Откройте приложение → **Настройки**.
2. Блок **«Синхронизация · GitHub Gist»**.
3. Вставьте токен в поле **GitHub-токен**.
4. Нажмите **«Проверить токен»** — появится `@ваш_логин`.
5. Нажмите **«Создать Gist»**:
   - если Gist ID пустой — будет создан новый **приватный** Gist;
   - если Gist уже указан — приложение спросит подтверждение и создаст новый.
6. Появится сообщение `Gist создан: <id>`.
7. Нажмите **«Сохранить ключи»**, затем **«Sync»**.

Готово: в Gist появился файл `producer-sales-helper.json`, а статус сменился на «Синхронизировано».

### 2.3. Если Gist уже есть

- Вставьте токен и нажмите **«Найти Gist»** — приложение найдёт приватный Gist с нужным именем файла.
- Либо вставьте ID Gist вручную: он виден в URL `https://gist.github.com/<username>/<gist_id>`.

### 2.4. Другие устройства

На новом телефоне или компьютере:

1. Откройте тот же сайт.
2. Настройки → вставьте **тот же токен** и **Gist ID** (или «Найти Gist»).
3. Сохраните и нажмите **Sync**.

Данные подтянутся из Gist. Токен хранится только в браузере этого устройства.

## 3. Telegram-бот

### 3.1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot`.
3. Имя: например `Sales Helper Bot`.
4. Username: должен заканчиваться на `bot`, например `my_sales_helper_bot`.
5. BotFather выдаст токен вида `123456789:AAH…`. Скопируйте его.

### 3.2. Узнайте chat ID

1. В приложении: **Настройки → Telegram-бот**.
2. Вставьте токен в поле **Токен бота**, сохраните.
3. Откройте своего бота в Telegram и отправьте `/start`.
4. Бот ответит примерно так:

```text
Это твой chat ID:
123456789

Скопируй его в приложении: Настройки → Telegram-бот → Chat ID...
```

5. Вставьте этот ID в поле **Chat ID** в приложении и сохраните.

Можно и без копирования: нажмите **«Узнать chat ID»** в приложении — оно возьмёт ID из последнего сообщения боту.

> Бот отвечает на команды только из чата, который указан в настройках. Если написать ему с другого аккаунта, он покажет chat ID, но данные не отдаст.

### 3.3. Проверьте отправку

В настройках нажмите **«Тест в Telegram»**. Бот должен прислать сообщение «Привет! Связь работает…».

Если тест не проходит:

- проверьте, что токен скопирован целиком, без пробелов;
- напишите боту `/start`;
- проверьте, что chat ID — это именно ваш личный ID (не username);
- корпоративный прокси может блокировать `api.telegram.org`.

## 4. GitHub Actions: напоминания по расписанию

Приложение умеет отправлять тестовые сообщения из браузера, но **автоматические напоминания** отправляет workflow в GitHub Actions. Ему нужны три секрета и одна переменная (для Mini App).

### 4.1. Добавьте секреты

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
| --- | --- |
| `GIST_ID` | ID приватного Gist |
| `GIST_TOKEN` | classic PAT со scope `gist` |
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |

`GIST_ID` виден:

- в URL Gist: `https://gist.github.com/<username>/<gist_id>`;
- в приложении после создания Gist;
- в ответе GitHub API, если открыть Gist.

Для `GIST_TOKEN` можно использовать тот же токен, что в браузере, или создать отдельный — так безопаснее: если один утечёт, второй продолжит работать.

Дополнительно на вкладке **Variables** добавьте `APP_URL` — публичный HTTPS-адрес приложения (например, `https://user.github.io/producer-sales-helper/`). Он нужен для кнопки Mini App; подробности в разделе 4.5.

### 4.2. Включите Actions

1. Репозиторий → **Actions**.
2. Если GitHub пишет, что workflows отключены, нажмите **I understand my workflows, go ahead and enable them**.
3. Слева выберите **Telegram bot & reminders**.
4. Нажмите **Run workflow → Run workflow**.

Первый запуск проверяет:

- доступ к Gist;
- токен бота;
- chat ID;
- отправку напоминаний и дневной сводки.

Через 1–2 минуты откройте запуск и посмотрите лог. Успешный запуск заканчивается сообщением вида:

```text
[bot ...] часовой пояс: Europe/Moscow, chat ID: 123456789
[bot ...] изменений нет
```

### 4.3. Расписание

Workflow уже настроен:

```yaml
on:
  schedule:
    - cron: '*/15 * * * *'
  workflow_dispatch:
```

То есть каждые 15 минут. GitHub не гарантирует точность: запуск может задержаться на 5–20 минут, особенно в начале часа. Для напоминаний «за час» этого достаточно; для секундной точности GitHub Actions не подходит.

Напоминание отправляется, когда:

- задача не выполнена;
- у задачи стоит галочка «Напоминать в Telegram»;
- до дедлайна осталось не больше `Напоминать за, мин` (по умолчанию 60);
- это напоминание ещё не отправлялось для текущего дедлайна.

Если задача просрочена больше чем на 48 часов, бот не спамит, а помечает её как отработанную. Такая задача останется в приложении и попадёт в дневную сводку.

### 4.4. Дневная сводка

Сводка приходит раз в день после часа, указанного в **Настройки → Час дневной сводки**, по часовому поясу из профиля. В сводке:

- задачи на сегодня и просроченные;
- пайплайн;
- выручка месяца;
- win rate;
- ближайшие задачи.

Чтобы отключить — снимите галочку **«Присылать дневную сводку»**.

### 4.5. Mini App в Telegram

Приложение открывается прямо внутри Telegram — это тот же сайт на GitHub Pages, без отдельной сборки и сервера.

1. Убедитесь, что Pages открывается по **HTTPS** (адрес вида `https://<user>.github.io/<repo>/`).
2. Скопируйте адрес из **Настройки → Telegram Mini App → URL приложения** (кнопка «Копировать»).
3. В GitHub: **Settings → Secrets and variables → Actions → Variables → New repository variable**:
   - имя `APP_URL`, значение — адрес из шага 2.
4. Запустите workflow **Telegram bot & reminders** вручную.
5. Откройте бота: кнопка **«Приложение»** появится в меню, её же присылает команда `/app`.

Что делает workflow:

- вызывает `setChatMenuButton` и ставит кнопку меню на Mini App (только когда `APP_URL` изменился);
- добавляет кнопку «Открыть приложение» к напоминаниям и дневной сводке;
- отвечает на `/app` кнопкой `web_app`.

Ограничения Telegram:

- URL должен быть **HTTPS**; `http://` и локальный `localhost` кнопка не примет.
- Inline-кнопки `web_app` работают **только в личных чатах** с ботом. В группах бот отправит обычную ссылку.
- Прямая ссылка `https://t.me/<bot>?startapp` требует включить **Main Mini App** у BotFather: `/mybots → Bot Settings → Configure Mini App`. Для кнопки меню и `/app` это не обязательно.

Внутри Mini App своё хранилище браузера. Один раз подключите Gist в **Настройки → Синхронизация**, чтобы видеть те же данные, что и на сайте. Токен хранится только в этом устройстве и не попадает в Gist.

Внутри Telegram работают системная кнопка «Назад», цвет шапки под тему приложения, haptic-отклик на действия и безопасные отступы снизу.

## 5. Проверка «полного цикла»

1. В приложении создайте задачу:
   - **Задачи → Задача**;
   - название: `Проверка бота`;
   - срок: через 30–60 минут;
   - повтор: без повтора;
   - галочка «Напоминать в Telegram» включена.
2. Нажмите **Sync** (или подождите автосинхронизацию).
3. В GitHub Actions запустите workflow вручную.
4. Проверьте Telegram — должно прийти напоминание.
5. Отправьте боту `/today` — задача должна быть в списке.
6. Отправьте `/done <id>` (ID показывается в сообщении) — задача закроется, а в приложении после Sync появится отметка.
7. Нажмите в боте кнопку **«Приложение»** — откроется Mini App с тем же интерфейсом.

Если что-то не сработало, смотрите раздел «Проблемы» ниже.

- **В течение дня:** добавляйте касания в журнал, двигайте сделки по канбану, закрывайте задачи.

## 7. Проблемы и решения

### «Gist не найден или нет доступа»

- Токен создан как classic и имеет scope `gist`?
- Gist принадлежит тому же аккаунту, что и токен?
- Gist именно **приватный**, а не secret/public? (Приложение работает и с public, но так данные видны всем — не надо.)
- ID Gist скопирован без лишних символов?
- Токен не истёк? Проверьте срок в GitHub → Developer settings.

### «Токен недействителен или истёк»

Создайте новый classic-токен, замените его в приложении и в секрете `GIST_TOKEN`. Старый отзовите.

### Бот не отвечает на команды

- Токен в приложении и в секрете `TELEGRAM_BOT_TOKEN` — один и тот же?
- Chat ID в настройках совпадает с чатом, из которого пишете?
- Напишите боту `/start` ещё раз.
- Проверьте, что workflow включён и последний запуск успешен.

### Кнопка «Приложение» не появляется

- `APP_URL` добавлен в **Variables** (или в Secrets)? Workflow читает оба варианта.
- Адрес начинается с `https://`? `http://` и `localhost` Telegram не примет.
- После добавления переменной workflow запускался заново? Кнопка меню обновляется только при изменении `APP_URL`.
- Бот открыт в **личном чате**? В группах inline-кнопки `web_app` недоступны — бот отправит обычную ссылку.
- Проверьте лог workflow: там будет `кнопка меню обновлена` или причина ошибки.

### Mini App открывается, но данных нет

- У Mini App **отдельное** локальное хранилище. Один раз подключите Gist в **Настройки → Синхронизация**.
- Токен из браузера туда не переносится — это сделано специально, чтобы секрет не гулял между контекстами.
- После подключения нажмите **Sync** — данные подтянутся из общего Gist.

### Напоминания не приходят

Проверьте по порядку:

1. **Actions включены?** Репозиторий → Actions → workflow не отключён.
2. **Секреты заданы?** Все три, без опечаток в именах. Для кнопки Mini App — ещё переменная `APP_URL`.
3. **Последний запуск успешен?** Откройте лог.
4. **Задача синхронизирована?** Нажмите Sync в приложении.
5. **У задачи есть срок и галочка «Напоминать»?**
6. **Часовой пояс верный?** Настройки → профиль → `Europe/Moscow` и т.п.
7. **`Напоминать за` не слишком маленький?** Если 0, бот напишет только после дедлайна; при запуске раз в 15 минут сообщение может прийти с задержкой.
8. **Не прошло ли 48 часов?** Слишком старые задачи бот не дублирует.
9. **Репозиторий не «заснул»?** После 60 дней без активности GitHub отключает cron. Запустите workflow вручную или сделайте любой коммит.

### Напоминание пришло дважды

- Проверьте, не запускались ли два workflow одновременно (должен спасать `concurrency`, но ручной запуск во время cron возможен).
- Если запуск упал между отправкой и записью Gist, следующий запуск может повторить сообщение. Это редкий случай; просто закройте задачу.

### Сайт открывается, но данных нет

- Это новое устройство: токен и Gist ID не введены.
- Или вы очистили данные браузера. Импортируйте бэкап или подключите Gist заново.
- Демо-данные — только локальные, пока не нажмёте Sync.

### «Файл данных слишком большой»

Gist API отдаёт файл до 1 МБ. Обычная CRM весит десятки килобайт. Если файл приближается к лимиту:

- удалите старые активности и задачи (они хранятся 90 дней как надгробия, потом исчезают);
- сделайте бэкап и начните новый Gist;
- не храните в заметках огромные тексты.

### Cron задерживается

Это нормально для GitHub Actions. Если нужна точность — запускайте workflow вручную или используйте внешний планировщик, который дергает `workflow_dispatch` через API. Но это уже отдельный сервис, а не «без сервера».

## 8. Обновление приложения

1. Измените файлы и запушьте в `main`.
2. GitHub Pages пересоберёт сайт автоматически.
3. Откройте приложение. Service worker обновит кэш в фоне; если видите старую версию — закройте вкладку и откройте снова или сделайте hard reload (`Ctrl+Shift+R`).
4. Если меняли список кэшируемых файлов, поднимите `VERSION` в `sw.js`.

Данные при обновлении не теряются: они в `localStorage` и Gist.

## 9. Резервная копия и переезд

- **Скачать бэкап** — полный JSON со всеми сущностями и настройками.
- **Импорт JSON** — заменяет данные на устройстве и, при включённой синхронизации, в Gist.
- **CSV** — только для таблиц и ИИ, не для восстановления.
- **Новый Gist** — создайте, затем импортируйте бэкап и нажмите Sync.

Храните бэкап в надёжном месте: в Gist тоже бывают сбои и случайные перезаписи.

## 10. Безопасность: коротко

- Публичный репозиторий — это нормально: в нём только код.
- Приватный Gist — это ваши клиенты и суммы. Не делайте его публичным.
- Токены — в браузере и секретах Actions, не в файлах репозитория.
- `GIST_TOKEN` — только scope `gist`, без доступа к коду.
- При утечке: отзовите токен в GitHub, создайте новый, обновите приложение и секрет.
- Не открывайте приложение с введённым токеном на чужом компьютере.
