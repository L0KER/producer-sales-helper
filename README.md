# Producer Sales Helper

CRM, воронка сделок, каталог битов, задачи, аналитика и напоминания в Telegram — для битмейкера, который продаёт биты, а не управляет таблицами.

Приложение работает как статический сайт на GitHub Pages: **без своего сервера, без включённого ПК и без базы данных, которую нужно администрировать**. Данные лежат в браузере и синхронизируются через приватный GitHub Gist. Напоминания присылает Telegram-бот, которого запускает GitHub Actions по расписанию. Тот же интерфейс открывается как **Mini App** прямо внутри Telegram.

> Для работы нужны только GitHub-аккаунт, Telegram и браузер. Всё бесплатно в пределах лимитов GitHub.

## Что внутри

| Раздел | Что делает |
| --- | --- |
| **Обзор** | Выручка, взвешенный пайплайн, win rate, средний чек, задачи на сегодня, воронка, источники, сделки без движения |
| **Клиенты** | Карточки артистов, менеджеров и лейблов: Telegram, email, страна, теги, история касаний, сделки и заметки |
| **Сделки** | Канбан по этапам и таблица: лид → на связи → переговоры → счёт → оплачено → сдан / отказ, drag-and-drop, быстрый переход на следующий этап |
| **Задачи** | Дедлайны, повторяющиеся задачи, привязка к клиенту и сделке, напоминания в Telegram |
| **Каталог** | Биты: BPM, тональность, жанр, теги, цена, статус (свободен / зарезервирован / в аренде / продан), создание сделки из бита |
| **Журнал** | Аутрич, ответы, звонки, оплаты и заметки — единая лента активности |
| **Аналитика** | Выручка по месяцам, воронка, источники, лицензии, топ клиентов, ручные KPI (аутрич, ответы, прослушивания, подписчики, реклама) |
| **Настройки** | Профиль, валюта, часовой пояс, Gist-синхронизация, Telegram, Mini App, бэкап, импорт, демо-данные |

Дополнительно:

- **PWA** — устанавливается на телефон и компьютер, открывается офлайн, кэшируется service worker'ом.
- **Экспорт для ИИ** — готовый Markdown-отчёт с промптом, JSON для моделей и CSV для таблиц.
- **Демо-данные** — один клик, чтобы посмотреть приложение с реалистичным набором сделок.
- **Без сборки и npm-зависимостей** — только HTML, CSS и ES-модули. Единственный внешний скрипт — официальный `telegram-web-app.js`; без него приложение работает как обычный сайт.

## Быстрый старт

### 1. Посмотреть локально

```powershell
npm run dev
# открой http://localhost:5173
```

Либо просто откройте `index.html` через любой статический сервер. `file://` не подойдёт: ES-модули и service worker требуют HTTP.

### 2. Загрузить демо

В пустом приложении нажмите **«Загрузить демо»** или откройте **Настройки → Демо-данные**. Появятся клиенты, сделки, задачи и биты — можно сразу щёлкать интерфейс.

### 3. Выложить на GitHub Pages

1. Создайте **публичный** репозиторий на GitHub (например, `producer-sales-helper`).
2. Загрузите файлы проекта в ветку `main`.
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, folder: `/ (root)`**.
4. Через минуту приложение будет доступно по адресу `https://<username>.github.io/<repo>/`.

Публичный репозиторий нужен только для бесплатного GitHub Pages. **Данные CRM хранятся не в репозитории, а в приватном Gist.**

### 4. Подключить синхронизацию

Подробная инструкция с картинками действий — в [docs/SETUP.md](docs/SETUP.md). Коротко:

1. Создайте classic PAT с единственным scope **`gist`**.
2. В приложении: **Настройки → Синхронизация · GitHub Gist** — вставьте токен, нажмите **«Проверить токен»**, затем **«Создать Gist»**.
3. Нажмите **«Сохранить ключи»** и **«Sync»**.

Gist создаётся **приватным**. В нём лежит файл `producer-sales-helper.json` — общая база для приложения и бота.

### 5. Подключить Telegram-бота

1. Создайте бота у [@BotFather](https://t.me/BotFather): `/newbot`, получите токен.
2. В приложении: **Настройки → Telegram-бот** — вставьте токен, сохраните.
3. Напишите боту `/start` — он ответит вашим `chat ID`.
4. Вставьте `chat ID` в настройки, сохраните.
5. В GitHub: **Settings → Secrets and variables → Actions** добавьте секреты:
   - `GIST_ID` — ID приватного Gist;
   - `GIST_TOKEN` — PAT со scope `gist`;
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   На вкладке **Variables** добавьте:
   - `APP_URL` — публичный HTTPS-адрес приложения, например `https://user.github.io/producer-sales-helper/`.
6. Включите Actions и запустите workflow **«Telegram bot & reminders»** вручную для проверки.
7. Откройте бота и нажмите кнопку **«Приложение»** — откроется Mini App.

Дальше workflow запускается каждые 15 минут: отправляет напоминания и дневную сводку, отвечает на команды `/today`, `/week`, `/pipeline`, `/deals`, `/stats`, `/done`, `/app`.

### Mini App в Telegram

Тот же интерфейс открывается прямо внутри Telegram — отдельная сборка не нужна:

- workflow при запуске проверяет `APP_URL` и ставит кнопку меню **«Приложение»** через `setChatMenuButton`;
- команда `/app` присылает кнопку `web_app`;
- напоминания и дневная сводка приходят с кнопкой «Открыть приложение»;
- внутри Mini App работают системная кнопка «Назад», цвет шапки под тему приложения, haptic-отклик и safe-area.

Нужен **HTTPS** (GitHub Pages даёт его автоматически) и **личный чат** с ботом: inline-кнопки `web_app` Telegram разрешает только в приватных чатах.

У Mini App своё локальное хранилище. При первом открытии внутри Telegram подключите Gist заново: токен останется на этом устройстве, а данные подтянутся из общего Gist.

Для прямой ссылки `https://t.me/<bot>?startapp` включите Main Mini App у [@BotFather](https://t.me/BotFather): `/mybots → Bot Settings → Configure Mini App`.

## Как это устроено

```text
┌──────────────────────────────┐        ┌───────────────────────────┐
│  Браузер (GitHub Pages)      │        │  GitHub Actions (cron)    │
│  HTML + CSS + ES-модули      │        │  scripts/bot.mjs          │
│  localStorage (мгновенно)    │        │  каждые 15 минут          │
└──────────────┬───────────────┘        └─────────────┬─────────────┘
               │  GitHub API (Gist)                    │
               └───────────────┬──────────────────────┘
                               ▼
                 ┌──────────────────────────┐
                 │  Приватный Gist          │
                 │  producer-sales-helper.json │
                 └──────────────────────────┘
                               │
                               ▼
                        Telegram Bot API
```

- **Локально — сразу.** Любое изменение пишется в `localStorage`, интерфейс не ждёт сети.
- **В облако — по возможности.** При включённой автосинхронизации изменения уходят в Gist через 1,5 секунды; раз в 5 минут приложение подтягивает чужие изменения.
- **Слияние — по записям.** Побеждает запись с более свежим `updatedAt`. Удаления хранятся как «надгробия» 90 дней, чтобы удаление на одном устройстве не «воскресло» на другом. Секция `bot` всегда берётся из Gist.
- **Бот — отдельный процесс.** Он читает тот же Gist, проверяет задачи и отправляет сообщения. Напоминание фиксируется в `state.bot.reminders[taskId] = dueAt`, поэтому не дублируется при каждом запуске.
- **Mini App — тот же сайт.** Бот открывает статический GitHub Pages в webview Telegram; отдельной сборки и сервера нет. Внутри работают системная кнопка «Назад», тема приложения, haptic-отклик и safe-area.

## Команды

```powershell
npm run dev      # локальный статический сервер на :5173
npm run check    # синтаксис, импорты и ссылки на файлы
npm test         # unit-тесты (Node 20+)
npm run bot      # запуск бота вручную (нужны env-переменные)
```

Для локальной проверки бота без Telegram и Gist:

```powershell
$env:BOT_STATE_FILE = "C:\temp\psh-state.json"
$env:DRY_RUN = "1"
node scripts/bot.mjs
```

Бот прочитает локальный JSON, покажет сообщения в консоли и ничего не отправит и не запишет.

## Переменные окружения бота

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `GIST_ID` | да* | ID приватного Gist с данными |
| `GIST_TOKEN` | да* | PAT со scope `gist` |
| `TELEGRAM_BOT_TOKEN` | да | Токен бота от BotFather |
| `APP_URL` | нет | Публичный HTTPS-URL приложения для кнопки Mini App |
| `GIST_FILE` | нет | Имя файла в Gist (по умолчанию `producer-sales-helper.json`) |
| `BOT_STATE_FILE` | нет | Локальный JSON вместо Gist — для отладки |
| `DRY_RUN` | нет | `1` — только логировать, не отправлять и не писать |

\* Если задан `BOT_STATE_FILE`, Gist не нужен.

## Приватность и безопасность

- **Токены не попадают в репозиторий.** PAT хранится в `localStorage` браузера, токен бота — в `localStorage` устройства и в секретах GitHub Actions.
- **Gist должен быть приватным.** В нём имена клиентов, суммы сделок и заметки.
- **PAT — минимальный.** Classic token только со scope `gist`. Не давайте ему доступ к репозиториям.
- **Публичный код ≠ публичные данные.** Репозиторий может быть публичным, но JSON с CRM лежит в приватном Gist.
- **Бэкапы.** «Скачать бэкап» сохраняет полный JSON. Импорт заменяет данные на устройстве (и в Gist при включённой синхронизации).
- **Чужое устройство.** Если открыть приложение на новом устройстве, данные появятся после ввода токена и Gist ID. Не оставляйте токен на чужом компьютере.

## Ограничения

- GitHub Pages и GitHub Actions — бесплатные, но не дают SLA. Cron может задержаться на 5–20 минут.
- Если репозиторий не проявляет активности 60 дней, GitHub отключает scheduled workflows. Достаточно запустить workflow вручную или сделать коммит.
- Gist API отдаёт файл до 1 МБ. Для обычной CRM этого хватает с запасом; для сотен тысяч записей — нет.
- Синхронизация не real-time: два устройства могут увидеть изменения друг друга с задержкой до 5 минут (или после ручного Sync).
- Приложение не хранит пароли и не работает с платежами. Это CRM и аналитика, а не бухгалтерия.
